处理错误

  2 分钟阅读  

简要概述

向服务发送 API 请求，可能会产生多种不同的错误响应，以下文档将会描述数据结构以及大致的原因。

在 gRPC 中，错误状态码是通过 google.golang.org/grpc/codes 包定义的，这些状态码遵循 gRPC 的官方规范。

响应体结构

查看完整的 proto 文件定义，关键部分如下：

// ErrorResponse 用于定义统一错误响应体
message ErrorResponse {
  Status error = 1;
}

// Status 用于定义统一错误状态码
message Status {
  int32 code = 1;
  string status = 2;
  string message = 3;
  repeated google.protobuf.Any details = 4;
}

一个 json 示例：

{
  "error": {
    "code": 5,
    "status": "NotFound",
    "message": "unknown service",
    "details": [
      {
        "@type": "type.googleapis.com/grpc_kit.api.known.status.v1.TracingRequest",
        "id": "b17f76dc51de4098bc974e5f2009c097"
      }
    ]
  }
}

自定义状态码

标准 Code 的限制

  • codes 包中的状态码（如 OK、NotFound、Internal 等）是固定的枚举值，不允许扩展；
  • gRPC 协议规定客户端和服务端必须使用这些预定义的状态码（范围 0~16），其他值会被视为非法；
  • gRPC 多语言实现中依赖标准化的错误码，自定义会引起兼容性问题；
  • 如负载均衡、重试等组件有些已经依赖预定义码的语义，所以不可自定义。

自定义状态码实现

虽然不能新增 code，但可以通过以下方式传递额外信息：

  • Status 的详情信息（Details）

    使用 errs.xxx.WithDetails 附加 Protobuf 消息：

    errs.InvalidArgument(ctx).WithDetails(&errdetails.LocalizedMessage{Locale: "en-US", Message: "Field 'email' is invalid"})

    客户端可通过 status.FromError() 和 st.Details() 解析。

  • Metadata（头部信息）

    通过 grpc.SetHeader() 或 grpc.SendHeader() 传递自定义元数据（如错误子类型）。

  • 错误消息（Message）

    在的消息体中包含结构化信息（如 JSON），但需客户端手动解析。

    errs.InvalidArgument(ctx).WithMessage("EmptyRegion The specified account has no access authority to any region.")
